# Gemini 4 NYC Hackathon: requirements

Source: the participant guide at https://cerebralvalley.ai/e/gemini-4-nyc/details (sign-in required), read 2026-11-20. Discord `#rules` has more rules for the day; not yet read.

## Every project
- Builds in one of the two problem statements below.
- Uses at least two Gemini 4 models (Argon, Carbon, Neon or Hydrogen), each with a clear job.
- Goes beyond a text box: voice, camera, video, images, documents or generated media are central to how it works.

## Problem statement 1: 5 Sigma
Pick a real task today's agents struggle with and build a Gemini 4 system that does it reliably. Prove it with an evaluation on inputs you didn't prepare for, compared with a simple baseline.
- What's the baseline (a single model call, an existing tool, or how people do it today), and how much better is the system?
- How does the test set reflect real use, including messy inputs and edge cases?
- Where does it still fail, and what changed after seeing those failures?

Guide's examples: a form-filling agent tested on 50 unseen messy documents against a single-model baseline; a coding agent scored on how many fixes pass the repo's own tests.

## Problem statement 2: Element 119
Build something that only works because Gemini 4 can see, hear and generate media. Video, audio, images or documents are the core input, and can be the output too. Use any Gemini 4 models plus the Decisions API and push them: longer footage, messier audio, more streams at once, faster real-time loops. Show where it breaks.
- What's the hardest input, and does it hold up?
- What does it get from raw media that a text description would lose?
- How far did it go before breaking, and what changed to get past that?

## Bonus track: Shopify
Build a commerce experience on shop.dev (product discovery to shopping agent). Open to all.

## Not allowed
- Text-only chatbots, demos that only run on scripted inputs, evaluations made up entirely of examples the team wrote to pass.
- Anti-project list: AI mental health advisor, basic RAG apps, Streamlit apps, image analyzers, "AI for education" chatbot, AI job application screener, AI nutrition coach, personality analyzers, AI medical advice, projects where a dashboard is the main feature, sports analyzers or coaches.
- Projects that violate legal, ethical or platform policies, or use code, data or assets you don't have rights to.

## Rules
- Repositories must be public.
- Teams of 1 to 4.
- The demo may show only features, code and functionality built during the hackathon; judges must be able to tell what was made at the event. Otherwise disqualification.
- No presenting an existing project as new work.

## Submission
- Due 5:00 PM. Public repo, a one-minute demo video of what was built on the day, all team members added.

## Judging
Round 1, in rooms: 3 min live demo + 2 min Q&A.

| Criterion | Weight | What it asks |
|---|---|---|
| Live demo | 35% | Works live on real, unrehearsed inputs; not slides or Figma |
| Proof it works | 25% | Evidence beyond the demo: a test against a baseline, an honest look at failures, or a plan the agent checks its output against |
| Creativity | 20% | Takes on a problem others avoid; goes beyond a text interface in a way that matters |
| Gemini 4 and Decisions API use | 20% | How well it uses at least two Gemini 4 models, each with a clear job, and the Decisions API; how far it pushes reasoning, speed or multimodality |

Round 2: top six teams on stage, same format, criteria weighted equally.
